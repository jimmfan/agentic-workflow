# Focused Wayfinder VS Code projection

- Status: completed

## Destination

Determine whether a thin native VS Code custom agent should replace inline
canonical Wayfinder execution for focused durable project understanding and
coordination.

## Current state

- Explicit focused-agent selection was feasible, but produced no better core
  outcome in the qualified EKS comparison and introduced a tool-policy and
  approval-flow regression.
- Automatic parent-to-focused-agent delegation failed the experiment stop-loss:
  one run repeated substantial investigation after the child returned and
  another wrote statuses outside the canonical Wayfinder state contract.
- The isolated route-marker comparison found no reliability advantage for the
  VS Code `SessionStart` hook over the compact portable root instruction.
- The focused custom agent, parent bridge, route hook, and narrow `PreToolUse`
  deletion guard are historical experiment artifacts, not current product
  behavior.
- General remains the semantic router and selectively executes the canonical
  Wayfinder skill inline. Explicit Wayfinder invocation remains available where
  supported.
